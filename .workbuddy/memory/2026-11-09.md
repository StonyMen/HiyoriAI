# 2026-11-09

## 通读 Hiyori 项目并梳理 Minecraft 陪玩模块

- 项目定位：Electron + TS 的 Windows 桌面 Live2D AI 助手，模块包括角色渲染与灵动层、TTS（Edge/Genie/豆包）、多端桥接（Discord/飞书/微信）、Codex 协作、异步任务编排（定时/子智能体/批量）、Minecraft 化身、STT 与 B 站直播（实验）。
- MC 模块路径 `electron/minecraft/`，约 7.9k 行。分层：工具层（`electron/tools/impl/minecraftCompanion.ts`、`minecraftGoal.ts`）→ `MinecraftRuntimeManager`（fork 子进程 + IPC）→ `workerEntry`（WorkerController，跟随/生存策略）→ `embodimentRuntime` + `actions/registry`（动作）→ `mineflayerAdapter`（约 3.5k 行，mineflayer + 4 个 patch）。
- 三套工具按职责分离：`minecraft_companion`（主智能体：连接/感知/移动/跟随/装备/丢弃）、`minecraft_goal`（唯一当前目标，TaskSlot 串行、替换即取消、checkpoint）、`minecraft_action`（子任务有限动作，仅 child executor 可用）。资源锁 `minecraft:body` / `minecraft:control` 防并发抢身体。
- 目标执行：goal → `taskManager.createAndStart`（type=background，toolsets=['minecraft']）→ 终态通过 `onTerminal` 唤醒 Hiyori 汇报。
- 动作表声明 26 个动作名，注册表实际接入 17 个；`use_container`/`eat`/`defend`/`retreat`/`sleep`/`harvest_crop`/`till_soil`/`sow_crop`/`execute_blueprint` 仅有类型定义，调用会返回 adapter_error(Unsupported)。（可作为后续补齐点）
- 生存反射：autoEat minHunger=16；饥饿 ≤6 且背包无食物才发 `food-shortage` 事件（不自行为狩猎/收割）；缺氧 `escapeToAir`；死亡取消当前动作并 fail 目标；敌对生物本能防御；`fluidSafety` 用 A* 破坏排除防止挖穿水/岩浆；跟随有 watchdog + stuck 判定 + 世界变化重试。
- 社交：`chatChannel` 聊天门控（单人或 owner 或消息含 hiyori）、`playerGaze` 射线盒体检测注视触发回应、回复同时 `say` 进游戏 + TTS 朗读 + mirror 到会话。
- 限制：仅局域网 + 离线认证；Minecraft 模式下 toolsets 只注入 minecraft-chat（含 run_command/take_screenshot）。

## 本机环境搭建与首次启动（踩坑记录）

- 项目无 `node_modules`/`out`，只能源码启动：`npm install` → `npm run dev`。无 .env 也可启动，LLM/TTS 在应用内设置面板填（SQLite 持久化）。
- `npm install` 直接跑会失败：electron 的 install.js 拉 GitHub 二进制 `ETIMEDOUT 20.205.243.166:443`。解决：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` + `--registry=https://registry.npmmirror.com`。
- postinstall 的 `electron-rebuild` 失败不是编译问题，而是 WorkBuddy 的 safe-delete shim 拦了 node-gyp clean（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，114 项 > 50 阈值）。因此 `npm install` 会以 4294967295 退出，但 patch-package 的 4 个补丁已生效。
- Electron 二进制需单独补：`ELECTRON_MIRROR=... node node_modules/electron/install.js`（dist 344MB）。Electron 41.0.2 → abi 145。
- better-sqlite3 需按 Electron ABI 重建，prebuild-install 走代理 502、绕代理超时，均不可用。可用方案：npmmirror 的 `node-v41.0.2-headers.tar.gz` 只有 include，需再下 `win-x64/node.lib`，组装成 `.tmp-node-headers/{include/node, Release/node.lib}`，然后 `node-gyp configure/build --target=41.0.2 --nodedir=...`。
- 若报 `LNK1103 调试信息损坏`：是上一轮按 Node ABI 编出的 obj/pdb 残留，手工删掉 `build/Release` 下的 *.obj/*.pdb/*.lib/*.exp/*.node 后重编即可。直接调 MSBuild.exe 会被 LOLBin 安全策略拦。
- 注意：给单条命令加 `ELECTRON_RUN_AS_NODE=1` 前缀会泄漏进会话环境，导致 `npm run dev` 把 Electron 当纯 Node 跑，报 `Cannot read properties of undefined (reading 'isPackaged')`。启动前用 `env -u ELECTRON_RUN_AS_NODE npm run dev`。
- 验证成功标志：窗口标题 “Hiyori - 看板喵”。

## 启动器脚本（2026-11-09 追加）

- 新增 `E:\MinecraftData\HiyoriAI\start-dev.bat`：cd 到自身目录 → 清 `ELECTRON_RUN_AS_NODE` → 设镜像变量 → 校验 node → 缺依赖时 `npm install` → `npm run dev`，非 0 退出时 pause。
- 桌面入口 `C:\Users\Stone\Desktop\Hiyori 开发模式.bat`：仅 `call` 项目内脚本，便于双击。桌面 `.lnk` 无法用 COM（WScript.Shell/Shell.Application 被安全策略拦），故用 bat 代替。
- 关键坑：**bat 内含中文时不能存 UTF-8**。cmd 按控制台 ACP(936/GBK) 逐行解析，UTF-8 中文会被切碎导致整行命令失效、报 “xxx 不是内部或外部命令”。正确做法：文件存 GBK(936) + CRLF、去掉 `chcp 65001`；纯 ASCII 的 bat 则任意编码均可。
- 关闭进程：`Get-Process electron | Stop-Process -Force`，再按 CommandLine 含 `HiyoriAI` 杀 node，端口 5173 随之释放。
